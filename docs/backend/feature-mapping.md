# Frontend Feature → Backend Contract Mapping

**Purpose:** For every module in [modules/overview.md](../modules/overview.md), which backend service/endpoints/DTOs it depends on, and what it depends on from other modules. The reference to consult instead of reopening Swagger when starting a module's implementation phase.

**Scope:** Mapping only — endpoint/DTO detail lives in each service's own doc under `docs/backend/<service>/README.md`.

**Related documents:** [backend/README.md](./README.md), [modules/overview.md](../modules/overview.md), [roadmap.md](../roadmap.md)

**When to read:** Starting a module's implementation phase, to know which `src/services/<service>` functions to build feature query hooks around.

**When to ignore:** Working purely on shared infrastructure with no business-data dependency.

## Notable gaps surfaced by this mapping

- **Order History has no list endpoint** — only `getOrder(orderId)`. Phase 8 can't build an order list table against this contract as-is.
- **Warehouses has no list endpoint** — only `getWarehouse(warehouseId)`. Phase 9's warehouse management screen needs one to exist before a table view is possible.
- **Shopping Cart has no backend counterpart at all**, confirming the Phase 0 architecture decision that cart state is client-only until checkout (see [state/zustand-strategy.md](../state/zustand-strategy.md)) — this mapping is the first real confirmation that decision was correct, not just convenient.
- Full detail on every other ambiguity/limitation is in [coverage-report.md](./coverage-report.md).
